# ルール

- ユーザーへの応答は日本語で行う
- 実装前に `AGENTS.md` と `/spec` 配下の関連仕様を確認する
- 実装は仕様に基づいて行う
- 仕様が不足している場合は、先に仕様を補う
- 完了した仕様ファイルは `/spec/finished` へ移動する
- `/spec/finished` は、明示的な指示または必要性がある場合のみ参照する

## OpenCode Bridge オーケストレーション

OpenCode Bridge の OSS agent は、通常の Codex 作業を補助するために使う。メイン agent は原則としてオーケストレーターとし
て振る舞い、作業の種類、リスク、範囲を見て OSS agent へ委譲するか判断する。

ただし、すべての作業を必ず委譲するわけではない。短い質問への回答、設定説明、ユーザーとの方針整理、低リスクな確認、明ら
かに小さい作業はメイン agent が直接進めてよい。

### 委譲してよい作業

- コード探索、依存関係調査、呼び出し元確認、影響範囲の洗い出しは `oss_kimi_rapid` を優先する
- ドキュメント、要約、変更履歴、テスト一覧、機械的な読み取り作業は `oss_flash_support` を優先する
- 単一ファイルまたは密結合した小さなモジュールの実装で、要件が明確かつテストがある場合は `oss_deepseek_pro` を検討する
- 範囲が曖昧な場合は、先に `oss_kimi_rapid` で調査してから実装可否を判断する
- 低〜中リスクの小さな実装で、Kimi のレートリミット余裕を活かしたい場合は `oss_kimi_impl` を検討する

### OSS agent に委譲しない作業

以下に関わる作業は、原則として `gpt-5.3-codex` が直接扱う。`gpt-5.3-codex` が利用できない場合は `gpt-5.5` を使う。

- 認証、認可、セッション管理
- エラー復旧、ロールバック、状態修復
- データベーススキーマ、マイグレーション、モデル定義
- 永続化、ファイルシステム整合性、データ耐久性
- CI、ビルド、デプロイ
- 3ファイル以上または複数モジュールにまたがる横断的な変更
- 課金、予算、監査、再実行、証明に関わる処理
- 静かな失敗がデータ損失やセキュリティ問題につながる箇所

### 重い実装の扱い

- 重い実装、複雑な設計判断、横断的変更、重要領域に近い修正、OSS agent の結果レビューでは `gpt-5.3-codex` を優先する。
- 重い実装を委譲する場合は `codex_heavy_impl` を優先する。
- `gpt-5.3-codex` が利用できない場合、または Codex 側で移行扱いになる場合は `gpt-5.5` を使う。
- 軽い実装は `oss_kimi_impl` または `oss_deepseek_pro` を検討してよいが、重要領域や失敗時の影響が大きい変更は OSS agentに委譲しない。

### OSS agent へ委譲する時のルール

- OSS agent は `fork_turns: "none"` で起動する
- 再帰的に Codex セッション内から `codex exec` を実行しない
- 同じファイルへ複数の OSS agent が同時に書き込まないようにする
- 書き込みを行う `oss_deepseek_pro` と `oss_kimi_impl` は単独で走らせる
- 同時に動かす OSS agent は最大2つまでにする
- OSS agent の結果には、確認したファイル、変更したファイル、信頼度、検証内容、失敗時の懸念、エスカレーション要否を含め
る
- 信頼度が LOW の場合、または MEDIUM で重要領域に近い場合は GPT-5.5/GPT-5.4 で再確認する

### agent の使い分け

| Agent | 用途 | 書き込み |
|---|---|---|
| `oss_kimi_rapid` | コード探索、依存調査、影響範囲確認、初回レビュー | 原則 read-only |
| `oss_flash_support` | ドキュメント、要約、変更履歴、機械的な補助 | 原則 read-only |
| `oss_deepseek_pro` | 小さく限定された実装、デバッグ、テスト追加 | workspace-write |
| `oss_kimi_impl` | 低〜中リスクの小さな実装、UI文言、型修正、軽いバグ修正、テスト追加 | workspace-write |
| `codex_heavy_impl` | 重い実装、複雑な設計判断、横断的変更、重要レビュー、OSS agent 結果の検証 | workspace-write |

## Claude Code から呼び出された場合のルール

- Claude Code から `codex exec` で呼び出された場合、渡されたタスク範囲を最優先する
- Claude Code が親オーケストレーター、Codex は委譲先の実行 agent として振る舞う
- 再帰的に `codex exec` を実行しない
- 指定されたファイル以外を変更する必要がある場合は、理由を説明し、最小限に留める
- 実装後は、変更ファイル、変更概要、実行したテスト、未確認事項、懸念点を報告する
- 重要領域、横断的変更、仕様不明な実装は、勝手に進めずエスカレーションする
