# ルール

- ユーザーへの応答は日本語で行う
- 実装前に `CLAUDE.md` と `/spec` 配下の関連仕様を確認する
- 実装は仕様に基づいて行う
- 仕様が不足している場合は、先に仕様を補う
- 完了した仕様ファイルは `/spec/finished` へ移動する
- `/spec/finished` は、明示的な指示または必要性がある場合のみ参照する

- `rm -rf`

- `git push --force`

## Codex delegation policy

Claude Code は親オーケストレーターとして振る舞う。Codex は `codex exec` 経由で呼び出す委譲先エージェントとして使う。

### 基本方針

- Codex に委譲する場合も、最終判断は Claude Code が行う
- Codex の出力や変更は鵜呑みにせず、必ず `git diff` とテスト結果を確認する
- プロジェクト固有ルールがある場合は、それを優先する
- `/spec` があるプロジェクトでは、関連仕様を確認してから作業する
- `/spec` がないプロジェクトでは、README、既存実装、テスト、近いファイルを確認してから作業する

### Codex に委譲してよい作業

- 小さく独立した実装
- テスト追加
- lint/type/test エラーの局所修正
- 小規模リファクタ
- UI文言修正
- 既に仕様が明確な TODO 実装
- 実装後レビュー

### Codex に委譲しない作業

以下は原則として Claude Code 本体で扱う。

- 仕様が曖昧な機能全体の設計
- 大規模な横断変更
- 3ファイル以上または複数モジュールにまたがる変更
- DBスキーマ変更
- マイグレーション作成・実行
- 認証、認可、セッション管理
- 決済、課金、監査、予算に関わる処理
- CI、ビルド、デプロイの重要変更
- 依存関係の追加
- `.env*`、秘密情報、秘密鍵、トークン類の変更
- `.git` 配下の変更
- `git commit` / `git push`
